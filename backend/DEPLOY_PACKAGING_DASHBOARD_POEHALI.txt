## Часть 0 — миграции БД (сначала)

Накатить два файла из репозитория, если их ещё нет в проде:

1) `db_migrations/V0724__packaging_shared_across_shifts.sql`
   — пакеты и этикетки (тип «Упаковка») в цехе — общий пул на все смены:
     `shift_number IS NULL` у рулона в цехе;
   — constraint: в цехе обязателен workshop_id (смена для упаковки не обязательна);
   — живые коробки упаковки в цехе → `shift_number = NULL`;
   — незакрытые заявки to_workshop только из упаковки → `shift_number = NULL`.

2) `db_migrations/V0725__reviews_wb_srid.sql`
   — колонка `reviews.wb_srid` + индекс;
   — буквенный srid отзыва WB (= rid сборочного задания) храним, чтобы
     привязывать отзыв к заказу/`wb_rid` и к швее после синка.

После миграций проверь:
```sql
SELECT conname FROM pg_constraint WHERE conname LIKE 'rolls_workshop%';
SELECT column_name FROM information_schema.columns
  WHERE table_name = 'reviews' AND column_name = 'wb_srid';
```

Без V0724 упаковка снова «привяжется» к смене и UI/бэкенд разъедутся.
Без V0725 отзывы WB с буквенным srid снова не найдут швею.

## Часть B — что должно попасть в код функций

### B1. shipments — упаковка без смены
`backend/shipments/index.py`:
- заявка/выдача/приём в цех: если ВСЕ позиции — тип «Упаковка»,
  `shift_number = NULL` (общий пул цеха);
- для ткани/тесьмы смена по-прежнему обязательна;
- дубликаты открытых заявок упаковки искать по `workshop_id` + `shift_number IS NULL`.

### B2. rolls — список упаковки без фильтра по смене
`backend/rolls/index.py`:
- для роли упаковщика (`packer` / `packer_returns`) рулоны упаковки
  в цехе отдавать по цеху, БЕЗ фильтра `shift_number`;
- ткань/тесьма для закройщика/швеи — как раньше, по смене.

### B3. kiosk — списание упаковки FIFO по цеху
`backend/kiosk/index.py`:
- `write_off_packaging`: FIFO по цеху, без привязки к номеру смены;
  сначала начатая коробка, потом свежая.

### B4. reviews — WB srid / rid
`backend/reviews/index.py`:
- при синке сохранять буквенный `wb_srid` из отзыва WB;
- матчить заказ по `orders.wb_rid = reviews.wb_srid` (и запасные пути);
- `rematch_wb_reviews` — допривязка старых отзывов без order_id после
  появления rid у заказов;
- в списке отзывов отдавать `wbSrid` / `wbRid` для UI.

## Часть D — проверка после деплоя

### Миграции и упаковка
1. В цехе у рулонов типа «Упаковка» `shift_number` пустой.
2. Заявка «в цех» только пакетами/этикетками — без выбора смены, создаётся.
3. Упаковщица любой смены видит одни и те же коробки упаковки в цехе.
4. Списание упаковки с киоска при закрытии заказа идёт (FIFO по цеху).

### Отзывы
5. После синка отзывов WB у записи с буквенным srid заполнен `wb_srid`.
6. В таблице отзывов видна связь с заказом/кодом; у швеи находится история,
   если заказ уже с `wb_rid`.

### UI
7. Главная: «Новые задания» — стол в кадре, FBS читается, «конвейер» не
   сыпется буквами.
8. Меню: имя «Фамилия И.О.», плашка логотипа, X закрытия не наезжает на текст.
9. Сотрудники: имена в формате инициалов, не обрезаются столбиком.
10. Рулоны: снаружи только поиск и «Заканчиваются»; фильтры — по шагам.
11. Терминал: при открытии смены нет выбора/карточки цеха; смены выбираются.
12. На «Материал на производстве» нет кнопок PDF простоя/резки без записи.
