# Промпт для агента CRM на poehali.dev — упаковки Бамбука, Вуали и Сетки для сайта (04.11.2026)

Скопируй текст НИЖЕ агенту CRM целиком.

---

Ты — агент проекта CRM на poehali.dev.

Проблема: сайт мегатюль.рф считает доставку Ozon по упаковке каждого размера,
которую CRM присылает в POST /api/crm/prices (поле items[].package:
lengthMm, widthMm, heightMm, weightG). Для четырёх тканей упаковки приходят,
а для трёх — ни для одного размера:

- Бамбук — SKU вида bambuk2_230 … (все 49 размеров)
- Вуаль  — SKU вида vyal2_230 …   (все 49 размеров)
- Сетка  — SKU вида grek2_230 …   (все 49 размеров)

Из-за этого сайт берёт коробку по умолчанию 600×400×80 мм, 600 г, и доставка
в цене этих тканей завышена примерно на 110 ₽ (Бамбук 200×230 до Ярославля —
230 ₽, а Молния того же размера с реальной упаковкой — 120 ₽).

Для сравнения, что сейчас приходит по другим тканям:
- krep2_230 (Шифон): 240×190×20 мм, 165 г
- mol2_230 (Молния), mramor2_230 (Мрамор): 240×220×50 мм, 275 г
- len2_230 (Лён): 240×190×30 мм, 195 г

Что сделать:

1. Найди, почему для bambuk*, vyal*, grek* упаковка не заполнена или не уходит
   на сайт: нет габаритов у товаров интернет-магазина, не нашлись парные товары
   маркетплейсов при копировании габаритов, другой артикул и т. п.

2. Заполни упаковку (длина, ширина, высота в мм, вес в граммах) для всех
   размеров Бамбука, Вуали и Сетки. Источник — габариты этих же размеров
   в карточках Ozon/Wildberries (как делалось при копировании габаритов
   с маркетплейсов для остальных тканей). Если у размера на маркетплейсе
   габаритов нет — возьми упаковку ближайшего размера той же ткани
   и отметь такие размеры в ответе.

3. Отправь обновлённые цены на сайт обычным способом (POST /api/crm/prices),
   чтобы в items для этих SKU пришло поле package. Остальную обработку не меняй.

4. Пришли список: ткань, сколько размеров заполнено, примеры упаковки для
   ширины 200, 400 и 800 см, и какие размеры заполнены по соседнему размеру.
