# Промпт для агента на poehali.dev — публикация накопленных функций

Скопируй текст НИЖЕ агенту на Поехали целиком. Фронт в Cursor/CRM уже готов —
без публикации этих трёх функций новые зарплаты и агенты на бою не заработают.

Не создавай функции с нуля: обновляй существующие по URL из CRM.
Промпты агентов живут В КОДЕ функций — не копируй их отдельно в поле System Prompt UI.

---

Ты — агент деплоя на poehali.dev. Опубликуй обновления трёх Cloud Functions из
репозитория CRM «Мегатюль». Базу данных и схему НЕ меняй. Новые таблицы/колонки
не создавай. Секреты не ротируй без нужды — проверь, что уже стоят.

## Общие правила

1. Открой проект → Cloud Functions.
2. Для каждой функции ниже: замени файлы пакета целиком из репозитория → Сохранить → Опубликовать / Deploy.
3. URL функции после публикации должен остаться ПРЕЖНИМ (см. ниже). Если URL сменился — остановись и сообщи: его надо синхронизировать во фронте.
4. Таймаут шлюза / max duration функции держи **не меньше 90 с** (МЕГАМАГ и МЕГАБУХ ходят во внешние API и модель).
5. После всех трёх деплоев прогони чеклист в конце.

**Что меняется этим релизом (зачем деплоим):**

  тянет данные в блок «ДАННЫЕ КАБИНЕТА», без второго круга tool-loop.
- Расширены интенты prefetch (`_OVERVIEW_INTENT`, `_MP_MENTION`) — вопросы
  «посмотри OZON / кабинет / карточки» больше не пропускают API.
- В SYSTEM_PROMPT явно: не писать «нет доступа к API», опираться на блок данных.
- Образовательный центр + web_search / read_page по официальным справкам площадок.

**Не делать:**
- Не вставляй `PROMPT_POEHALI.txt` в UI System Prompt — источник правды `SYSTEM_PROMPT` в `index.py`.
- Не клади ключи OZON/WB/YM в env функции — они читаются из `marketplace_integrations`.

## 3) Зарплата — salary

**URL (уже в CRM `src/lib/salaryApi.ts`):**
https://functions.poehali.dev/16c53065-6726-495b-9e59-70d16dd9328f

**Файлы:**
- `backend/salary/index.py`
- остальные файлы пакета salary (`authz.py` и т.д.), если они есть в функции на Поехали —
  синхронизируй пакет целиком, не оставляй старый `index.py` со старой пагинацией.

**Секреты:** как были (`DATABASE_URL` и пр.). Схему БД не трогай.

**Что меняется этим релизом (критично для вкладки «Зарплата»):**

1) **Пагинация админских начислений — по рабочим дням, не по 15 строкам.**
   - `?page=1` → до **2 календарных дней** `accrued_for` целиком.
   - На странице все начисления этих дней (все сотрудники/роли), а не «первые 15 строк».
   - `totalPages` считается по числу уникальных дней, не по числу строк.
   - Иначе фронт (день → роль → сотрудник) показывает дырявые дни («7 из 40»).

2) **Бонус швей за выработку (акция 01.09–30.09.2026) закончился.**
   - `?sewerBonus=1` после 01.10.2026 отвечает `{ "active": false, "sewers": [] }`.
   - Не возвращай `state: finished` со старым списком — виджет на дашборде уже снят с фронта.

3) **Номер заказа в начислениях — заказ покупателя, не строка системы.**
   - В ответах `orderNumber` для OZON берётся из `ozon_posting_number` без суффикса `-0001`
     (позиция в отправлении). Для WB/YM — `wb_order_id` / `ym_order_id`, иначе `order_number`.
   - Иначе в финансах светятся позиции/внутренние id, и непонятно, какой заказ шили.

**Не делать:**
- Не возвращай пагинацию «LIMIT 15 OFFSET …» по строкам.
- Не меняй формулы начислений/выплат/кассы в этом релизе — только пагинация дней,
  пустой sewerBonus после акции и ярлык номера заказа.

## 4) Чеклист после публикации

### МЕГАМАГ
1. Админ/менеджер → Агенты → МЕГАМАГ открывается.
2. Короткий вопрос «требования к карточке на OZON» — ищет справку, в статусе есть ссылка docs.ozon.ru / seller-edu.
3. Вопрос «посмотри кабинет / остатки / SEO» — в ответе опирается на данные (не «нет доступа к API»).
4. Нет `Failed to fetch` на обычном вопросе (если таймаут — проверь duration ≥ 90 с и что Deploy прошёл).

### МЕГАБУХ
1. Бухгалтер или админ → МЕГАБУХ открывается.
2. Вопрос по отчёту/кнопке в программе — отвечает по-человечески, при необходимости идёт в официальную справку.
3. Подпись собеседника — Имя Фамилия.

### Зарплата
1. Админ → Зарплата → список начислений: на одной странице **целые дни** (не обрубок из 15 строк).
2. Листание «по дням» меняет набор дат `accrued_for`.
3. Виджет/запрос бонуса швей не отдаёт старую акцию как активную/finished-список — пустой `sewers`.
4. В строках начислений номер — **заказ покупателя** («заказ 01234567»), не `-0001` позиция
   и не внутренний id начисления. У сотрудника во «Моя зарплата» то же.
5. Касса, выплаты, тарифы — как раньше (фронт уже с папками/группировками).

### Если что-то упало
- Сообщи: какая функция, HTTP-код, первые строки лога, совпадает ли URL с CRM.
- Не чини фронт и не меняй БД в рамках этого задания.
