# мегатюль.рф: город покупателя, доставка в цене и начисления блогерам — задание разработчику

Сначала сделайте пункты 1–2 из `megatul-prices-api.md`: витрина должна брать цены из ERP, а не из формулы в коде. Без этого задание ниже не заработает.

## 1. Город покупателя: обязателен

- При первом заходе определить город по IP (DaData `iplocate/address` или аналог) и показать плашку «Ваш город — Москва? Да / Выбрать другой».
- Выбор города — поиск с подсказками. Уже есть `/api/ozon/suggest` и `/api/ozon/points`, используйте их.
- Город хранить в cookie `megatulle_city` (название + координаты / id населённого пункта Ozon), 90 дней. Показывать в шапке с возможностью сменить.
- **Пока город не подтверждён:**
  - на витрине вместо цены — «Укажите город, чтобы увидеть цену с доставкой»;
  - кнопки «В корзину» и «Оформить» неактивны;
  - сервер (`/api/pay`) отклоняет заказ без города с ошибкой `400`.
- Если Ozon не доставляет в город: «В ваш город пока не доставляем», заказ не оформить.

## 2. Доставка включена в цену

- **Точка отгрузки:** Ярославль, ул. Елены Колесовой, 48. От неё считать тариф Ozon Доставки до города (или выбранного ПВЗ) покупателя.
- **Цена для покупателя** = цена размера из ERP (`/api/catalog` → `sizes[].price`) + доставка до его города.
  - Отдельной строки «доставка» нет, на витрине одна итоговая цифра.
  - Подпись: «Доставка в ваш город уже в цене».
- **Несколько товаров в заказе.** Доставка считается один раз на всю посылку по общему весу и размеру, а не на каждый товар. На карточке товара можно показывать цену с доставкой одной штуки. В корзине итог пересчитывать по всей посылке.
- Тариф кешировать по городу на 12–24 часа, чтобы не дёргать Ozon на каждой карточке.
- **При оплате сервер сам пересчитывает итог:** цены из базы + тариф Ozon для города заказа. Сумме из браузера не верить.

## 3. Начисление блогеру

Правило: блогер получает **15% от стоимости товаров без доставки**. С доставки он не получает ничего.

```
база блогера = Σ (цена размера из ERP × количество)   // без доставки
начисление   = база блогера × 15%
```

Пример: Бамбук 200×230 стоит 1190 ₽, доставка в Москву 260 ₽. Покупатель платит 1450 ₽, блогеру начисляется 1190 × 15% = 178,50 ₽, а не 1450 × 15%.

- Процент брать из настройки, а не из кода: ERP может его поменять.
- Начислять только по оплаченным заказам. При возврате начисление сторнировать.
- В кабинете блогера «Сумма товаров» показывать без доставки.

## 4. Что передавать в ERP в заказе (`GET /api/crm/orders`)

```json
{
  "number": "MT-1024",
  "status": "paid",
  "city": "Москва",
  "total": 1450,
  "deliveryPrice": 260,
  "partnerCode": "anna_home",
  "partnerPercent": 15,
  "partnerAmount": 178.5,
  "items": [
    { "sku": "bambuk-200x230", "price": 1190, "quantity": 1 }
  ],
  "delivery": { "city": "Москва", "price": 260, "parcels": [] }
}
```

- `items[].price` — цена товара **без доставки**.
- `deliveryPrice` — сколько доставки заложено в заказ.
- `partnerCode`: если покупатель пришёл не по ссылке, передавать пусто, а `partnerAmount` — 0.

## Проверка

1. Покупатель без города не видит цену и не может оформить заказ.
2. Покупатель из Москвы видит 1190 + тариф Ozon Ярославль → Москва. Из Ярославля — 1190 + местный тариф.
3. Заказ по ссылке блогера: в кабинете блогера начислено 15% только от 1190 ₽.
4. В ERP заказ пришёл с городом, доставкой и начислением блогера.
