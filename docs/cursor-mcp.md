# Подключение Cursor к проекту

Внешний ИИ-агент (Cursor, Claude Desktop и подобные) может читать проект через
MCP-сервер. Он даёт **только чтение**: код, структуру базы, данные из базы и
журнал действий. Менять проект через него нельзя — правки идут обычным путём
через git.

## Что нужно один раз добавить в проект

Два секрета в разделе «Ядро → Секреты»:

| Секрет | Зачем |
|---|---|
| `MCP_AGENT_TOKEN` | Пароль агента. Без него адрес открыт всему интернету. |
| `MCP_GITHUB_TOKEN` | Чтение кода из приватного репозитория. Права: Contents → Read-only. |

Имя именно `MCP_GITHUB_TOKEN`: короткое `GITHUB_TOKEN` занято самой платформой
под её собственную интеграцию с GitHub, секрет с таким именем не добавляется.

## Настройка Cursor

Cursor → Settings → Tools & MCP → New MCP Server. Либо вручную создать файл
`~/.cursor/mcp.json` (для всех проектов) или `.cursor/mcp.json` внутри рабочей
папки (только для этого проекта):

```json
{
  "mcpServers": {
    "proektnaya": {
      "url": "https://functions.poehali.dev/9066944a-2bf6-4f4b-8dbd-3e938d87b96f",
      "headers": {
        "Authorization": "Bearer ВАШ_MCP_AGENT_TOKEN"
      }
    }
  }
}
```

Вместо `ВАШ_MCP_AGENT_TOKEN` — значение секрета `MCP_AGENT_TOKEN`.

После сохранения в Settings → Tools & MCP сервер `proektnaya` должен загореться
зелёным и показать шесть инструментов.

## Инструменты агента

| Инструмент | Что делает |
|---|---|
| `list_files` | Дерево файлов проекта с размерами. Можно ограничить папкой. |
| `read_file` | Файл целиком по пути, например `src/App.tsx`. |
| `search_code` | Где встречается строка: имя функции, текст на экране, таблица. |
| `db_schema` | Таблицы базы; с параметром `table` — колонки таблицы. |
| `db_query` | `SELECT` по базе, максимум 200 строк за раз. |
| `audit_log` | Журнал: кто, когда и что сделал в системе. |
| `app_errors` | Сбои приложения: что упало у сотрудников и в функциях. С `summary=true` — сводка за неделю. |

## Что наружу не отдаётся никогда

- Секреты проекта: ключи маркетплейсов, строка подключения к базе.
- Личные документы сотрудников: таблица `personal_data`, паспорта, телефоны,
  адреса, ИНН, СНИЛС, номера карт.
- Действующие токены и коды входа: по ним можно войти от чужого имени.
- `node_modules`, `dist`, lock-файлы — чужой код, который только мешает агенту.

Запись запрещена на двух уровнях: разрешён лишь `SELECT`, и соединение с базой
открывается в режиме read only, так что Postgres сама отклонит любую правку.

## Если что-то не работает

- Красный сервер в Cursor и 401 в логах — пароль в `mcp.json` не совпадает с
  секретом `MCP_AGENT_TOKEN`.
- «GitHub ответил ошибкой 404» — `MCP_GITHUB_TOKEN` не выдан на нужный репозиторий
  либо у него нет права Contents: Read-only.
- «Поиск по коду сейчас недоступен» — GitHub ограничил частоту поиска. Агент
  должен взять `list_files` и читать файлы напрямую.
- Агент видит устаревший код — в репозиторий попадает то, что закоммичено; после
  правок в проекте дождитесь коммита.

## Журнал сбоев

Раньше ошибки жили только в консоли браузера сотрудника и исчезали вместе с
закрытой вкладкой. Теперь они сохраняются в таблице `app_errors`: текст ошибки,
страница, кто работал, версия системы. Туда попадают падения компонентов, упавшие
запросы и ответы функций с ошибкой 500–504.

Намеренно НЕ записываются: устаревшая версия страницы после обновления (система
чинит это сама) и короткие обрывы связи в цехе — иначе журнал забился бы шумом, а
настоящие сбои в нём утонули.

## Как вернуть правки агента в проект

Агент правит код у себя в клоне репозитория. Дальше обычный git: коммит и push
в репозиторий, а затем правки подтягиваются в проект. Прямо через MCP-сервер
изменить проект нельзя — так и задумано.
